# 知遇测评：设计基线与保留式界面升级

## Overview

产品侧是面向个人的自我理解与生活问题整理工具；本轮交付物是设计原型与开发交接。评审侧是桌面优先的功能树工作台。它们是两种用途，评审外框保持中性，不把外框风格强加给八套产品主题。

优先级：当前用户明确要求 > 原始交接包中已确认的产品事实 > V2 可靠流程 > V3 有效浏览与操作反馈 > 新视觉提案。任何合并、删除、改变范围必须写入裁决，不能把自己的上一版当作完整原始要求。

已确认要保留：四个入口的职责与顺序、我的名称、16PF主线及方向说明、单因子瓶子、每日轻探索、模拟因子实验、详细人物、八套原始主题、低幅呼吸、减少动态、草稿与本人观察、实际尝试结果、来源边界、原单快照，以及完整职责映射。

本轮有独立产品评审与实施角色。源代码检查、运行验证与真实像素评审分别报告，不将尚未取得的截图或未运行的浏览器测试计为通过。

## Colors

单一运行时源是 `handoff/themes-v4.json`。`tools/build_themes.py` 生成 `prototype/themes-v4.css` 和 `prototype/themes-v4.js`。主题数值在 JSON 中定义；本文 frontmatter 镜像默认晨光奶油的少量公共值。变更源后必须重新生成，不允许只改生成文件。

八套原始方向各有完整的场景渐变、纸面、文字、按钮、五个专题角色、笔记页、边线、滚动条和语义状态。晨光奶油为珊瑚橙、蜜桃、暖金；糖霜星云为玫粉、杏橘、糖霜黄；莓果汽泡为莓粉、葡萄紫、冰蓝；青柠薄雾为青柠、翠绿、透青；流光天幕为蓝、轻紫、晚霞粉；海盐晴蓝为晴蓝、海青、薄绿；夜航星云为深蓝、星紫、冷光青；琥珀潮汐为深梅、赭橙、流金。

V1–V3新增的青屿晨光、杏桃晚风、海盐晴空、灵感紫在独立“历史候选”组保留。用户尚未确认最终发行集合，不能把12个预览方向称作最终产品规格。

颜色映射：

|源角色|输出变量|消费者|
|---|---|---|
|paper / surface|--paper / --surface|页面、输入、弹层、底栏|
|primary / on-primary|同名变量|按钮、选中、焦点、进度|
|field-a/b；scene-a/b/c + scene-gradient|同名变量|持久柔光画布；主题预览与收敛圆环|
|topic-1…5|同名变量|专题分类、内部辅助色|
|notebook / notebook-ink|同名变量|我的个人积累页|
|warning / danger / success 及 bg|同名变量|来源范围、失败、成功状态|
|unknown-fill|公共中性角色|暂无依据的因子与画像节点|

禁止再次把固定的青柠、杏桃、雾蓝、淡紫、奶黄写到所有主题的专题组件。深色主题需要检查正文、图标、分段器、弹层、输入、瓶子和错误状态。人物本身的肤色与服装是保留的素材，禁止通过全局色相滤镜把人物一起染色。

## Typography

中文使用系统字体栈，不打包字体。正文15–16px，次级说明12–13px；紧凑设置不缩小正文、题目或主要触控区域。首页主线标题29px，页面标题约29px。辅助说明允许更小，但不能承载唯一的重要费用、隐私、错误或样例身份信息。

## Layout

探索页390px采用一个重点主题与两列相关主题；窄于360px改为单列，避免中文信息挤压。专题页先开始或续接最近整理，再按需查看完整提纲。答题保持单任务。四主页面共享全局潮汐渐变，答题和长文保留安静阅读表面。首页保留174px居中原人物、稳定16PF主线与两张同级主入口；小尝试不能替换主标题或主操作，仅在已存在时以次级入口紧接主任务。认识工具、每日轻探索、假设实验、报告样例与阅读移至探索，首页以本轮六入口契约为准，现实问题与助理分别保留探索和助理导航；生活整理及最近整理同时由探索承接；快捷记录、全部记录和小尝试保留在我的。助理输入优先，不堆叠功能入口。个人页空状态先提供实际起点；有资料后才突出数量。报告保留章节导航、依据与本人异议区域；16因子默认收起，正文优先呈现情境解读。助理输入位于历史之前；引用统一由输入框内入口选择。

产品内容采用手机宽度，宽屏不把长文无限拉长。评审工作台为可搜索功能树、实际预览和可隐藏说明区；窄屏转为可开关侧栏。图形预览框不伪造手机状态栏。

## Elevation & Depth

主要层级由明暗、分组和空间建立。产品装饰集中在主任务/专题封面；正文区安静。工作台仅以轻边框区分目录、工具栏与预览。不在每个功能上叠加独立强渐变与大阴影。

## Shapes

保留轻微不对称的主任务与笔记页轮廓，统一按钮和表单边界。主题视觉差异通过完整场景和颜色角色表达；交互命中范围、业务状态与导航不随主题改变。

## Components

产品既有组件由 `components.js`、`app.js`、`flows-v2.js` 负责，V4优先扩展这些共享对象。`product.css` 是现行共享视觉层，取代 V3/V4 两个互相叠加的视觉文件；后者仅作为未加载的历史源码保留。加载顺序是 ui.css（基础）→ experience-v2.css（兼容结构）→ themes-v4.css（生成颜色角色）→ product.css（现行组件）。禁止重新载入旧V3/V4视觉文件。主操作52px、次操作48px、工具操作44px，控制圆角16px；卡片按任务采用20–26px。选项用边框、字母标记与文字表达选中状态，不用整块深色淹没题目。

主题 / 人物 / 密度 / 字号 / 减少动态为独立设置；切换保留答卷、输入与引用。呼吸只作用于装饰背景，12–16秒级；文案、题目、数值保持静止。原有点击反馈继续保留，系统减少动态优先。

无障碍目标为WCAG 2.2 AA，但本轮没有宣称全站符合性认证。实际检查触控、焦点、IME、减少动态和关键对比；真机与完整辅助技术验证单独列明。

## Do's and Don'ts

每次修改先写保留清单，再写收益与反证，再做计算样式和行为检查。代码还在不证明入口仍可达；主题名还在不证明整套主题仍独立；测试数还在不证明本轮已经验证；产品树列全也不证明所有服务已接入。

正式题源、计分、常模、真实模型、账号、支付、退款和同步均不可由视觉设计假设为已实现。禁止根据三道交互示例生成16PF结果。正式服务与付费参数待实际业务接入确定。

## 当前视觉优先契约：双主色柔光与整体材料适配
